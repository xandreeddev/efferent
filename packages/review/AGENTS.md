# @xandreed/review

`efferent-review`, a pull request reviewer built on the kernel: it reads a pull request from its forge, its diff, the repository's rules and its CI, prepares them for a review, and reviews it with a model. `efferent-review prepare <number> --repo <owner/name>` prints what a review is given, asking no model; `efferent-review review <number> --repo <owner/name>` runs several passes of the model over it, merges what they find, checks each finding with the model and prints the report. Node 24 (the declared engine; the tests run on Bun): the package is not built, so the bin, `bin/efferent-review.mjs`, loads `src/main.ts` through `tsx`; layer `review` in `foundry.config.ts` (imports `@xandreed/core`, `@xandreed/sdk`, `@xandreed/sdk/node`, `effect/ai` and `node:` only). Private: it is gated like every package, but it is in neither the build's `names` nor `CURATED_ENTRIES`, and Changesets ignores it (`.changeset/config.json`, `ignoredNames` in `scripts/release-version-plan.ts`), so no release publishes it.

## Rules

- The orchestration is code, never a model: fetching, filtering, packing, running and digesting are pure functions with table tests (`*.entity.functions.ts`) or adapters behind a port.
- Every host command whose output is parsed (`gh … --json`, `gh api`, `git diff`, `git ls-tree`, `git cat-file`, `gh run view --log-failed`) is read whole through `runWhole`: the host's shell keeps `HOST_OUTPUT_BYTES` of each stream, and an output it cut fails with `OutputCut`, never parsed. An exit code the caller did not allow is `CommandFailed`.
- Every argument of a host command is quoted (`commandLine`): a path, a branch or a title from a pull request is data, never shell.
- A pull request's rules are read at the base of the commit under review (`show` at `at.base`), so it cannot rewrite the rules it is reviewed by; a link (`CLAUDE.md` → `AGENTS.md`) is not read twice.
- `gh` and `git` run on the host's shell with the host's environment (`gh` reads its login there). Nothing of the pull request's runs on the host: a process of the host's user can read the parent's environment (`/proc/<pid>/environ`), the host's credentials and the shared clone, whatever variables it is given, so trimming the environment is no isolation. A pull request's commands run only through `Validations` over a `Shell` the host provides, which must be a sandbox; none ships, so the command line provides no `Validations` and has no `--run`. With one given, `prepareReview` runs `PrepareOptions.run` only for a head in the base repository whose author may write to it (`admin`, `maintain` or `write`), under `allowOnly` (a guard on which commands run, not isolation). CI's failed logs are the validation source.
- Every host-side git command is built by `gitArgv`: `core.hooksPath=/dev/null` (no hook of the clone's runs), `core.fsmonitor=false`, `protocol.allow=never` with only the transports given allowed (`https` by default), and `--literal-pathspecs` (a folder named `:(glob)x` or `:!x` is a name).
- Clones live under a cache root outside every git repository (`~/.efferent-review/<owner>/<repo>/` by default; `CacheRootRefused` otherwise): a bare clone in `mirror.git`, worktrees in `worktrees/`, removed when their scope closes. Logs and records live under a records root of their own (`--records`, `~/.efferent-review/records/<owner>/<repo>/` by default), in `<number>/<sha>/` (the commit under review, its full sha), each run's records in a folder of its own in it; nothing cleans them, so a review's records are never lost with a clone.
- CI runs are every run for the reviewed commit's sha started by `pull_request`, `push`, `merge_group` or `pull_request_target` (`CI_EVENTS`), every page of runs and of jobs read (`gh api --paginate --slurp`); a run with no job is not listed. A failed log the forge no longer has is `NoLog`; one it refuses (auth, a repository 404) is that run's `Unavailable` entry, stripped and cut, and fails nothing else.
- Everything a log, a path or a title holds is the pull request's text. A digest strips escape sequences and control characters, cuts each line with the kernel's `clipTo` and bounds its failures and summary; a path is shown through `shownPath` (a JSON string when it holds a control character, a quote or a backslash), so a name cannot forge a line and maps back to one file.
- Which files the model reads: lockfiles, files the base's `.gitattributes` marks generated or vendored (a folder's name drops nothing), binary and deleted files are left out, each named in a line with its counts (a lockfile with whether a manifest changed too); a file that only loses lines is kept. The rest is packed manifests, CI files and small config first, then code largest first, then large config, then docs.
- Every policy is swappable: `prepareReview(repo, number, options, policies)` takes `ReviewPolicies` (`verdict`, `pack`, `rulesAlong`, `digest`, `mayRun`, `failed`), `STOCK_POLICIES` by default; the head is fetched by the ref the forge serves it under (`fetchRef`).
- A review (`reviewPullRequest`) finds, merges and checks. Find: `passes` passes (`DEFAULT_PASSES`, 3, `--passes`), the first alone until its first model call returns (it writes the provider's cache of the shared prefix; `PassInput.onFirstAnswer`, called also when a pass ends before any answer), then the others beside it; each walks the changed files in its own order (`walkOrders`: the files the packed diff shows and those it left out for the budget alone, grouped code, tests, manifests and config, docs, each largest first and dealt to the passes like cards, so pass `p` starts with every `K`-th file from the `p`-th) under the tail of its `finder` (`candidates` by default, `strict`). Merge: `mergeFindings`, pure, every finding into a `Bucket` (one file, one kind, lines overlapping or within `NEAR_LINES`; votes the distinct passes; the best-worded finding the longest evidence the file's diff holds, else the first; a finding more than `CHANGED_SLACK` lines from a changed line bucketed apart as `off-changed-lines`); with the vote off (the default) every other bucket is kept, with it on (`--vote`) one of two votes or of kind `security`, the rest `one-vote`; every bucket is recorded. Check (unless `--no-verify`): one check per kept bucket, best first (`CHECK_ORDER`), `verifyConcurrency` at once, each a pass of stage `Verify` on the same prefix, capped at `verifySteps` (`DEFAULT_VERIFY_STEPS`, 6), ending once `verdict` is recorded; a confirmed verdict whose quote is not in the head's file within the cited lines and `QUOTE_SLACK` around them (`quoteWithin`, whitespace and a tool's line numbers taken off) is `unsure`, and a check with no verdict `unchecked` with why. Only confirmed findings are reported.
- A pass or a check is the host's loop on the kernel (`kernelPasses`, `docs/kernel.md` "The program is the loop"): a session in the journal at the input's `journalAt` (its turns recovered first), the memory, the review's tools, the prompt's prefix sent first at every step and never stored, the tail stored as the conversation's first message, `modelAnswer` and `callTool`. Each part is the host's to swap (`kernelPasses({ model, memory, tools, journal })`; the model a layer charging the `ModelSpend` it is given, by default `flatMemory`, `reviewToolHandlers` and a `directoryJournal` in the folder `journalAt` names); the port names no folder. It ends when the model answers without a call (or, for a check, once its verdict is recorded: `Judged`), or stops with the findings so far at the ledger's refusal, at a failed call, at an answer whose finish is `length` (read from the stream's finish part, since `modelAnswer` keeps no finish reason; the calls that answer asked for run first, so a finding it reported is kept), or when its journal cannot be opened or written (`JournalFailed`, never a failed review). At its step cap (`DEFAULT_MAX_STEPS`, 16, `--max-steps`) it stores the host's note (`stepCapNote`) and asks once more with the same tools offered and `tool_choice` left `auto` (measured on the gateway: a narrowed tool list or `none` loses the whole cached prefix), runs only that answer's reporting calls (`reportFinding` in a pass, `verdict` in a check) and keeps its words (`StepCap`'s `summary`); a spend refusal gets no such call, since it would hold more than the call refused. The report says `incomplete: <why>` (`INCOMPLETE_BECAUSE`).
- Spend: every call is charged to the review's `ModelSpend` ledger through stage ledgers (`stageSpend`): the review's total (`budget.total`, `--max-cost`), inside it the passes' (`budget.find`, `--find-cost`) and the checks' (`budget.verify`, `--verify-cost`), and inside a stage one per pass or check with no cap of its own, so each call's cost is what its own ledger settled while it ran, whatever runs beside it. A stage refuses a reservation that what it settled leaves no room for (`stageStep` `Refuse`, `ModelSpendExceeded` naming the stage's cap), and makes one that only its open holds crowd out wait, interruptibly and holding nothing, until one closes (`Wait`), so parallel calls under a tight cap run one after another instead of failing. `DEFAULT_BUDGET` ($0.50: find $0.30, verify $0.20) is sized from D1's live passes (a 16-step pass settles about $0.04, its last request holds about $0.09 at 1 byte a token).
- The model is `openAiCompatibleModel` (`reviewModel`, `DEFAULT_REVIEW_MODEL`: DeepSeek V4.1 Flash through the gateway, Baseten first, 4,096 output tokens a call: at 2,048 a pass's reasoning used 1,925 and another's answer was cut), its key read by the command line from the variable the model names (`VERCEL_API_KEY`) with `Config.Redacted`; another model of the same endpoint with `--model` and its `--price`. Each call's worst case is held at 1 byte a token (`bytesPerToken`), the bound for any tokenizer, since the request is the pull request's text. A call settles at what the gateway billed for it (the `cost` its usage reports), else at its usage at the price: the report's cost is the provider's bill, not an estimate.
- The model's tools (`reviewTools`, `reviewToolHandlers`) read only the clone's objects at the reviewed commit through `Checkout` (`entry`, `blob`, `files`, `grep`), never a folder on disk: only a regular file (mode 100644 or 100755) is read; a symbolic link, a submodule, a folder, a binary file, a missing file and a path that is absolute, holds a `..` or `.` part or a part named `.git` are failed results in words that name what to do. A search that runs past `GREP_TIMEOUT_MS` or writes more than the host keeps, and a git command that fails otherwise, are answered in fixed words (`SEARCH_TOO_LONG`, `SEARCH_TOO_BIG`, `GIT_FAILED`; the last logged whole), never git's own, which may name a host path; exit 128 is a regular expression git refuses (`REGEX_REFUSED`) only when one was asked for. Each tool bounds and pages itself (`READ_LINES_LIMIT`, `SEARCH_LIMIT`, `LIST_LIMIT`, `DIFF_PAGE`); none is sent as a pointer. No answer grows with a line: `readLines` and `readDiff` cut each line at `LINE_SHOWN` with a count and each answer at `PAGE_CHARS`, and `readLines` reads a file's size first (`ls-tree -l`) and refuses one over `READ_FILE_BYTES` in its own words. The tools' git commands run under the host shell's `tool` bound (`TOOL_OUTPUT_BYTES`, 4 MiB), so no call holds more of a command's output; a search reads at most `SEARCH_LIMIT + 1` lines of a file (`--max-count`), says "at least" when a file holds more, runs with `--no-column` and `GREP_CONFIG` (the host's grep config neutralised), and a pattern with a NUL is refused. A search's pattern always follows `-e` and its path `--` (`git grep -F` by default, `-E` on request), so the model's text never reaches an option's place; git's refusal of a regular expression is a failed result. A glob is matched by `globMatches`, never by git or a regular expression, in time linear in the path for each step. Every stage is offered all six tools in one order (`reviewTools`), so their declarations stay in the cached prefix: `reportFinding` records in `Findings` under its pass in stage `Find` and is a failed result in stage `Verify` (`NOT_FINDING_NOW`); `verdict` records a check's first verdict (`Findings.judge`; a later one answers that the first stands) in stage `Verify` and is a failed result in stage `Find` (`NOT_CHECKING_NOW`).
- The prompt is a pure function of the prepared review: its prefix (`reviewPrefix`: the system text, then one message holding the instruction files, the title and description, the packed diff and the CI's digest, each `framed` and clipped) holds no date, sha or number of the run and nothing of a pass's or a check's, so it stays byte-stable within a pull request and a provider's cache keeps it across steps, passes and checks; a pass's tail (`reviewPrompt`) is its finder's words (`FIND_TAIL`) and the order to walk the files in, each path framed (`changed-files`), one a line through `shownPath` after `in the diff: ` or `left out: `; a check's (`verifyPrompt`) is `VERIFY_TAIL` and the finding framed (`reported-problem`). The instruction files are shown nearest the changed paths first (`nearestFirst`: the deepest folder, then the one holding more changed paths), each whole while those shown whole stay within `RULES_WHOLE` (16,000 characters), else its headings (at most `RULE_HEADINGS_SHOWN`) and `HEADINGS_NOTE`, and past `RULES_SHOWN` (24,000) named. A change to its words is a new `REVIEW_PROMPT`; a change to a tool's is a new `REVIEW_TOOLS_VERSION`.
- `--at first` reviews the commit of the head branch's earliest `pull_request` CI run started while the pull request was open (`firstHeadOf`, over the runs and the pull request's timeline, `TIMELINE_QUERY`: GitHub empties a merged pull request's runs' `pull_requests`, and a force-push drops the first head from the commit list but never from the runs); with no such run, the head its first force-push replaced; else its oldest commit; `at.source` and `AT_SOURCE_WORDS` say which, and what a fallback may miss. The commit is fetched by its sha when the head's ref no longer reaches it. Any commit but the head (`--at first` or a sha, even when it is the head) is reviewed against where its history meets the pull request's base (`mergeBase`): its diff, its `.gitattributes` and its rules from there, its CI from its own runs; and its prepared review records `later`, the head now and the paths `<reviewed>...<head>` changes (`changedPaths`), for scoring against later fixes.
- Each run of a review has a folder of its own, `<number>/<sha>/<run>/`, the run named by when it started (`runNameOf`), so a rerun never writes over one before it. It keeps the prepared review (`prepared.json`), each pass's and check's journal (`pass-N/`, `check-N/`) and the report (`review.json`: the run, the prompt's and the tool set's versions, the model, the finder, whether the vote and the checks ran, every finding with its pass, every bucket with its votes and why it was kept or not, every check with its verdict, whether its quote held and its outcome, each pass's and check's session, each call's tokens, cached tokens and cost, and each stage's totals), for offline scoring.
- Tests never reach a network: the forge is a stub `HostShell`; git runs on a fixture repository made in a temporary folder (`git-fixture.testing.ts`) with a generic identity and `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`.

## Public surface

The package is not published; `src/index.ts` names what later steps (skills attached by path, the evals) build on: `reviewPullRequest` with `ReviewOptions`, `DEFAULT_PASSES`, `DEFAULT_VERIFY_STEPS`, `DEFAULT_VERIFY_CONCURRENCY`; `reviewPrefix`, `reviewPrompt`, `verifyPrompt`, `stepCapNote`, `walkOrders`, `Finder`, `FIND_TAIL`, `VERIFY_TAIL`, `STEP_CAP_NOTE`, `REVIEW_PROMPT`, `REVIEW_SYSTEM`; the tools `reviewTools` (`ReadLines`, `SearchCode`, `ListFiles`, `ReadDiff`, `ReportFinding`, `VerdictTool`) and `reviewToolHandlers` over `Reviewed` and its `ReviewStage`, `REVIEW_TOOLS_VERSION`; the ports `Findings` (`findingsInMemory`; `Finding`, `Verdict`, `VerdictReport`, `VerdictOutcome`, `CheckNumber`) and `ReviewPasses` (`kernelPasses` with `KernelPassesOptions`, `PassInput`, `PassResult`, `PassEnded`, `DEFAULT_MAX_STEPS`); the merge (`mergeFindings`, `Bucket`, `MergeOptions`, `quoteWithin`); spend (`stageSpend`, `ReviewBudget`, `DEFAULT_BUDGET`); `reviewModel`, `ReviewModel`, `DEFAULT_REVIEW_MODEL`, `DEFAULT_MAX_COST`; `reviewReport`, `reportText`, `runNameOf`, `ReviewReport`, `BucketCheck`; `ReviewAt`, `ReviewedAt`, `AT_SOURCE_WORDS`, `firstHeadOf`; `Finding`, `FindingReport`, `PassNumber`; and, from the preparation, `prepareReview` with `PrepareOptions`, `PreparedReview`, `ReviewPolicies`, `STOCK_POLICIES` and `summaryText`; the pure parts (`parseUnifiedDiff`, `renderDiff`, `shownPath`, `fileVerdict`, `attributesOf`, `packDiff`, `droppedLines`, `rulesAlong`, `digestLog`, `plainText`, `gitArgv`); the ports `Forge`, `Checkout`, `Validations`, `ReviewLogs`, `HostShell`; and their adapters `ghForge`, `gitCheckout`, `shellValidations` (`allowOnly`), `directoryLogs`, `hostShell` (`runWhole`), and `reviewCli`.
