# @xandreed/plugin-render

Agent output a host renders: versioned render surfaces over the host's `RenderStore` and admission, a journal feed of client frames with SSE and WebSocket transports, and the `render_component` tool through which a model publishes one exact, admitted component. Node 24 and Bun; layer `plugin-render` in `foundry.config.ts` (imports core; `node:http` only as the type `sseNodePeer` takes, and `node:zlib` only when a peer compresses, loaded then by a dynamic import so the entry stays loadable where Node's modules are not).

## Rules

- Admit before any write: the size check and `UiOutputAdmission.validate` run before the store or journal sees a component, and a refused one is never replaced.
- Keep a store's guarantees in the store (`RenderStore` contract, `src/ports/render.port.ts:20-44`), each in its write's own transaction: a write under a fence lower than the highest the surface and message accepted is `forbidden`, `plan` refuses a frozen surface and a generation that is not the highest planned plus one (`conflict`), `commit` is idempotent by `operationId`, and records never mix across threads or principals.
- A publish whose plan another writer beat (`conflict`) re-hydrates and decides once more, never twice: the same content resumes that version, other content plans the next.
- Derive operation ids with `operationIdOf` / `fillOperationIdOf` (stable per run, surface, generation and node, parts percent-encoded) and versions with `versionIdOf`; never join raw ids. Every id is a brand (`ThreadId`, `PrincipalId`, `RenderMessageId`, `SurfaceId`, `VersionId`, `NodeId`, `OperationId`, `RevisionId`; the scope's `runId` is core's `RunId`): mint one with `.make` where the host creates it.
- Identical content (same `signatureOf`) opens no generation: it commits only the nodes still missing, then completes.
- Releases are exact (`UiRelease`, both hashes) and never resolved through a latest alias; the host supplies the scope (`UiOutputContext`), the model only props and evidence ids.
- A failing feed ends the connection like a finished one and is logged, never sent to the client.
- Read a session's live frames only through `sessionLive`, which follows the feed's own session as its principal (as the tail does): never a channel address the host did not authorize.
- A transient frame (a `live` payload) has no sequence: never give it an SSE `id`, never let it move the cursor, and send none before the ready frame. Start following `live` before the snapshot is folded or the backlog read, and hold its payloads in the feed's own bounded queue (`liveBuffer`, suspending, never sliding: a full queue stops pulling `live`, so a pull-based source loses nothing) until the ready frame: never let the journal side wait on the live one.
- A projection's services (`FeedProjection<R>`) and a snapshot fold's (`SnapshotFold<R>`) are the stream's: `frames` runs both inside the stream, never with a context captured when the feed was made, and their failures stay `RenderError`.
- A snapshot is a record at its `head` sequence, sent only to a client at cursor 0 or past the head, and the tail follows from the head: never send it to a client resuming at a cursor in `1..head`, and never give it a sequence other than the head (a reconnecting client resumes from it).
- `kinds` reaches the tail (`JournalTail.read`, then `Sessions.read`), so other kinds are never loaded; the feed still drops other kinds a tail returns, and moves the cursor past every record read. A `frames` call without `kinds` reads the tail with the feed and the cursor alone, as before.
- `SseTransport` ends its peer (`SsePeer.end`) exactly once when the frames end, finished or failed, and never after the client left (`closed` won). A compressing `sseNodePeer` flushes after every write and completes the write only once that flush is done: a response that takes bytes has the frame by then, and a frame never waits in the compressor for the next. With a client that takes none, the write still completes and the compressed frame waits on the compressor's output side.
- Keep SSE and WebSocket frames identical; a wire change reruns `bun run docs:generate`, which writes the frames into `docs/event-reference.md`.
- A behaviour change starts as a check in `src/render-surface.conformance.ts` or `src/render-transport.conformance.ts`, which the shipped adapters then pass.

## Public surface

- Plugins and defaults: `renderSurfacePlugin`, `renderFeedPlugin`, `uiOutputPlugin`, `renderSurfaceDefaults`, `renderFeedDefaults`. `uiOutputPlugin` provides the toolkit in `UiOutputTools`; the host serves it with `UiOutputHandlersLive`.
- Ports: `Render`, `RenderStore`, `JournalTail`, `RenderFeed` (types `RenderSurface`, `RenderOpenOptions`, `FeedProjection`, `FeedFramesOptions`, `FeedSnapshot`, `SnapshotFold`, `RenderTransport`, `SsePeer`, `SocketPeer`), `UiOutput`, `UiOutputAdmission`, `UiOutputJournal`, `UiOutputContext`, `UiOutputTools`. Adapters: `RenderLive` / `openSurface`, `MemoryRenderStoreLive` / `makeMemoryRenderStore` (type `MemoryAnnotation`), `RenderFeedLive` / `makeRenderFeed`, `SessionsJournalTailLive`, `sessionLive` (a session's `SessionChannel` as a feed's `live` stream), `SseTransport`, `WebSocketTransport`, `sseNodePeer`, `sseHeaders`, `UiOutputLive`, `UiOutputHandlersLive`; the tool `RenderComponent` in `uiOutputToolkit` (an effect/ai `Toolkit`, not a core capability).

- Functions: `signatureOf`, `versionIdOf`, `operationIdOf`, `fillOperationIdOf`, `missingNodesOf`, `outputScopeOf`, `proposalOf`, `fromOutputError`, `isFrozenRefusal`, `isConflictRefusal`, `progressOf` (type `SurfaceProgress`), `describeError`, `ssePreamble`, `encodeSse`, `decodeSse`, `encodeSocketFrame`, `decodeSocketFrame`, `socketResumeOf`, `nextPollMs`, `payloadOf`, `sseContentEncodingOf`. The `./output` subpath (`src/output.ts`) exports the output half alone.

Both entries name each export, and `quality/exports-have-consumers` checks each one: sdk's tests, the scripts (the plugin reference, the packed consumers) and the docs' code blocks import some, and the rest, which no first-party code imports, are tagged `@public` at their declarations (core's `ConformanceFailure` at its re-export in `src/index.ts`).

## Tests

- Kits: `src/render-surface.test.ts:21` runs `renderSurfaceConformance` over `RenderLive` and `makeMemoryRenderStore`; `src/render-transport.test.ts:24` and `:44` run `renderTransportConformance` over both transports and `renderFeedConformance` over `makeRenderFeed`. `src/render-surface.conformance.test.ts` is the surface kit's self-test: a careless store with no generation check must fail exactly the generation checks. The transport kit's self-test (`src/render-transport.test.ts:30`): an SSE transport that never ends its peer, and one that also ends it after the client left, fail exactly its end check. The feed kit's self-test (`:75`): its check list, and a feed that ignores the snapshot, or the kinds, or follows `live` late, or drops live payloads its client has not taken, fails exactly the checks that use them. `foldEqualsReplay` (`:161`, `:165`) passes a fold that equals its projection's replay and fails one that drops a record, folds kinds the projection skips, merges into a stale state or fails. `src/render-transport.test.ts` also covers `payloadOf`, a projection that requires a store, a fold and a projection that require different services, a snapshot read page by page, an empty journal's snapshot, an invalid head, the `liveBuffer` bound (a finite source larger than it arrives whole, in order, the feed pulling no further than the bound while it waits; a bound outside 1 to 65 536 refused), a live stream that fails after a payload, a tail read without kinds as before, `sseContentEncodingOf`, and `sseNodePeer` over `node:http`: Brotli, gzip and uncompressed responses that decode to the frames sent and end without the host, a compressed frame that arrives before the next is written, a compressed write that completes only once its flush gave a response that takes bytes the frame (read at the server, where the compressor is piped into the response: no client or deadline decides it), and the uncompressed headers and bytes unchanged. These read each response off a `node:net` socket (`overSocket`), never through `node:http`'s client: Bun 1.3.0's can read part of a body off the socket and never give it, or the end, to the response's listeners, which fails a test of a response that stays open by its deadline and one of a response that ends by the runner's timeout. `src/render-output.test.ts` covers admission before commit and `render_component`'s text; `src/render-tail.sessions.test.ts` the session tail over a stub `Sessions`, `kinds` passed to `Sessions.read` among it; `src/render-live.sessions.test.ts` `sessionLive` over a stub `SessionChannel`.
- `packages/sdk/src/events-guide.test.ts` serves a session's journal through `RenderFeedLive`, `SessionsJournalTailLive` and `SseTransport`, and starts a cold client from the session folded at its head (checked with `foldEqualsReplay`), then follows only the kinds it shows; `packages/sdk/src/session-channel.journey.test.ts` streams a turn another request runs to a feed through `sessionLive`, and starts a cold client mid-turn from a snapshot whose fold runs while the turn streams its reply; `scripts/verify-packages.ts:457` imports the packed package on Node, and `:491` runs the transport kit, the feed kit and a Brotli `sseNodePeer` response there.
