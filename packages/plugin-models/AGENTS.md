# @xandreed/plugin-models

The models plugin: the routed `LanguageModel` (opencode, google, anthropic, openai and openai-codex, plus configured chat-completions and Anthropic Messages endpoints), the fast `UtilityLlm`, the `ModelCatalog`, and the `AuthStore` and `SettingsStore` they read (`.efferent` files with `storage: "local"`, memory with `storage: "memory"`), with the Anthropic and OpenAI subscription sign-ins and one HTTP proxy transport for every call. Node 24.5 and Bun; layer `plugin-models` in `foundry.config.ts` (imports core, `effect/ai`, `effect/http`, `effect/socket`, the provider packages `@effect/ai-anthropic` and `@effect/ai-openai`, which no other package may import, `undici`, `ws` and `node:`; it tells Bun by `process.versions` and reaches its `fetch` and `WebSocket` as globals, importing no `bun` module; its tests, layer `plugin-models-tests`, add `bun:test`, `fast-check` and `effect/testing`).

## Rules

- Build a provider per request from a freshly resolved key (`buildProvider`), never at layer build: a sign-in or a model switch applies on the next call.
- Name a built-in provider only in its profile (`PROVIDER_PROFILES`, `src/llm/provider-profile.entity.functions.ts`): its catalog, each model's images and efforts, and the route a model is sent over. The catalog, `imageInputFor`, `reasoningEffortsFor` and `buildProvider` read the table; a builder serves a route, never a provider name.
- Send every outbound call (providers, compatible endpoints, OAuth refreshes, the subscription's WebSocket) through the `ModelsTransport` when one applies, as `throughTransport` does in `src/llm/router.ts`. Managed Node direct and proxy transports use scoped undici agents/pools with header/body timeouts zero; never change the global dispatcher. Only the exact managed direct transport yields to an explicitly provided `FetchHttpClient.Fetch`, even when its value equals the global fetch. Inspect Reference presence without resolving its default. Explicit host transports and proxies stay authoritative; Bun keeps its native behavior.
- Read what a routed call is built over (`CurrentModelEndpoints`, `CurrentModelSettings`, `ModelsTransport`, a subscription session cache of the layer's own: `layerProviderServices`) once, where the router's layer is built, and pass it to each call as an argument (`ProviderServices`). Replay no captured context on a call but the layer's stores (`Context.pick(AuthStore, SettingsStore)`): the references a call carries (its call policy, retry policy, prompt cache key, trace content, log annotations) are the call's own.
- Keep `storage: "memory"` off the disk; with `storage: "local"`, read and write files through `src/storage/json-file.ts`: only a missing file is empty, one it cannot use fails with `auth.corrupt` or `settings.corrupt` and is left as it was.
- Never change the stores' service keys. `AuthStore` and `SettingsStore` (`src/ports/auth-store.port.ts`, `src/ports/settings-store.port.ts`) are this package's ports, but they keep the keys core declared them with, `@xandreed/core/AuthStore` and `@xandreed/core/SettingsStore`: plugins' `provides` and `requires`, hosts' bindings and the plugin reference name them.
- Keep reading what older releases wrote: `auth.json` and the settings files keep their formats, and a settings file that still holds the `sandbox` or `viMode` key decodes with the key unread (`EngineSettings` names neither, and a store keeps it when it writes another).
- Refresh a provider's token one at a time and commit it only if the provider still holds the credential refreshed, so a login or logout made meanwhile wins.
- Never repeat a secret in an error: an unknown option key is named without its value, proxy URLs go through `redactCredentials`, and a token endpoint's refusal quotes its body only through `tokenRefusalText`, which replaces every secret the request sent first.
- Keep credential secrets `Redacted` (`Credential` decodes them so, and `TokenResponse` decodes a token endpoint's answer so): unwrap one with `Redacted.value` only where a request is built, and compare two with `Equal.equals` (`isSameToken`), never `===`. Write a credential only in its encoded form (`encodeCredential`, which `writeAuthFile` applies to every entry it writes), never through `JSON.stringify`, which writes `"<redacted>"` and so erases the secret; the round-trip test in `src/auth/localAuth.test.ts` guards it.
- Keep `CLAUDE_CODE_SYSTEM` byte-exact and first on Anthropic OAuth calls: the provider refuses the token otherwise.
- Add an Anthropic beta to a request's `anthropic-beta` header (`withAnthropicBetas`, `mergeBetas`), never set the header: the client's own betas (structured outputs, documents, the subscription's) must stay.
- Send the thinking binding (`thinkingPrefixMismatch`, `CurrentThinkingPrefixMismatch`; default drop_block) only to a model whose profile `bindsThinking` with effective Adaptive thinking, with its beta; keep its untyped request fields in `providers.ts`, and never let reading `input_transformations` fail or change a response.
- A route that reads no images (`imageInputFor`, an endpoint's `images`) is sent label lines (`promptWithImageLabels`), never the image and never a provider error.
- Read the full `CurrentModelRetryPolicy` Reference at logical-call execution, validate it with `ModelRetryPolicy`, and use `modelRetryDefaults`; no persisted settings or plugin-option overlay. Its stable key is `@xandreed/plugin-models/CurrentModelRetryPolicy`. One physical-send counter and deadline cover primary and a distinct fallback; reserve its final slot only when at least two attempts are allowed. An absent or identical fallback retains the primary's full cap.
- Keep retry ownership in `src/transport/resilient-http-client.adapter.ts`: retry classified RateLimit/Transient/Timeout transport or rejected-status failures only before successful response handoff. Inspect rejected bodies under 64 KiB and pending-read bounds, cancel discarded responses before another send, and never replay one-shot stream/FormData bodies. Sleep the greater of capped backoff and capped Retry-After, within the shared deadline; a long hint never proves quota.
- Bound pending headers, each pending body read and later network operations by the policy and remaining deadline. Preserve stamped Timeout and exact typed reader errors at the existing SDK erasure boundaries. Do not reinstate router watchdogs, in-flight counts or tool-handoff wrappers: tool and callback work is outside retries and model timeout wrappers. OAuth token requests are outside model-request retry scope.
- A 200 empty response, body/SDK decoding failure or SSE failure is final at the transport boundary. The loop's existing pre-content stream-to-settled fallback gets a fresh logical budget but reuses the frozen step and its single prepared header; do not reevaluate model/step policies, append StepContext or add headers. The engine and ephemeral attempt state remain private; terminal model.called facts are separate metadata and never change the prepared header.
- Account for each actual model attempt once through core's execution-time `CurrentModelCallRecorder`. A logical call keeps one `ModelCallId` across retries and configured fallback, with a continuing physical ordinal. Record discarded pre-handoff failures before another send; hand successful responses to raw native/compat/Codex observation under the same attempt identity. A new stream-to-settled logical call keeps the existing header. Outside turns the recorder deliberately does nothing.
- Preserve raw usage presence and cumulative snapshots before SDK defaults or empty/object/tool validation. Unknown is distinct from genuine final zero; initial streaming output zero stays Partial until final output is actually reported. Anthropic input excludes its cache shares; other supported protocols include them. Provider completion is independent of downstream response acceptance, and rebuilding a response (thinking diagnostics or a host hook) must retain its private attempt capability.
- Settle one terminal recorder ACK per attempt, including cancellation and lost ACK. A recorder failure stops retries, fallback and tools; it never becomes provider Transient or a second terminal record. Internal channels carry `TurnError` precisely. Fixed SDK/utility signatures and stream finalizers carry the original recorder `TurnError` as a defect for the existing turn-boundary restoration; never wrap, stringify or ignore it. Only terminal claim/ACK bookkeeping and durable append are protected from interruption; post-ACK host callbacks remain interruptible.
- Decode an OpenAI-compatible body or stream chunk with `src/llm/chat-wire.entity.functions.ts` (`decodeChatCompletion`, `decodeStreamChunk`); one that does not decode fails as an `AiError`, and an empty 200 response is a transient failure (`rejectEmptyResponse`) unless the loop has set `CurrentEmptyResponseTolerance`.
- Interpret provider codes, statuses and narrowly scoped context evidence in the `provider-failure` entity pair, before the SDK discards their meaning. The captured clients in `provider-client.adapter.ts` fail raw settled responses and SSE errors with stamped `AiError`s; preserve known usage, request ids and original raw diagnostics while removing request credentials and query values from those diagnostics. A valid OpenAI event status supplies semantic evidence independently of the actual HTTP status.
- Preserve explicit engine failure stamps of every kind through all adapter wrappers, Codex included. Copy concrete reason constructors and their declared evidence, keep metadata-less network reasons unchanged, and use core's `modelFailureMessageOf` for fixed native failure descriptions. Known permanent semantic failures bypass retries/fallback; Unknown gains no automatic transport retry eligibility. A generic output-token limit remains a cut response, not context overflow.
- Stamp context overflow in the actual built-provider wrapper with that invocation's selection and known neutral limits. Messages supplies the resolved context window and effective sent output cap, including alias settings and call-policy precedence; unknown bounds remain absent. Keep this typed value beside the private route rather than parsing public settings JSON or reading billing facts. A fallback's evidence belongs to its own route. Other routes, including Codex which strips its output cap, must not invent a sent limit. Copy the identity and bounds before suspension and for each failure; preserve hard recorder errors.

- `modelSettings` is a static full-selection map captured once alongside endpoints. Per-request caps/effort precede settings and documented profiles; unknown Messages IDs require an explicit cap. Keep stored ModelCallPolicy decoding unchanged and validate effective values at the provider edge.
- The shared Messages builder separates API/gateway authentication from subscription OAuth. Preserve opaque keys, explicit empty keys, version headers and the merged beta header; a configured bearer key never implies subscription instructions.
- Model-specific thinking and forced-tool validity comes from profile traits. Keep wire erasure only in providers.ts, and test settled, streaming and object paths before changing compatibility logic. Config failures are InvalidRequest, separate from authentication.

- Plan cache slots over the actual prepared SDK payload through the captured client's settled and streaming methods. Candidates are identified by immutable per-call object references from `CurrentPromptCacheFrame`, never a shared mutable set or serialized sentinel. Count fanout per location, preserve caller controls and lifetime order, and keep tools/system/messages/nested content in semantic order.
- Per-model `promptCache` defaults to Auto5m. Auto uses only the stable prefix; TopLevel deliberately follows the provider's last-block semantics. A Messages endpoint's `cacheControl: false` removes legitimate null fields and refuses caller markers; never walk business input or tool schemas as cache metadata. Strip recognized volatile engine bookkeeping before every protocol serializer.

## Public surface

- Plugin and models: `modelsPlugin` (also the default export; no `.live` alias), `LanguageModelLive`, `LanguageModelSelectionLive`, `UtilityLlmLive`, `ConfiguredModelCatalogLive`, `roleModelView`, `imageInputFor`, `reasoningEffortsFor` (`ReasoningEffort`); the configured endpoints `ModelEndpoint`, `ModelEndpoints`, `CurrentModelEndpoints`, plus `ModelThinking`, `ModelSettings`, `ModelSettingsMap`, `ModelSettingsError`, `PromptCacheSettings` and `CurrentModelSettings`; `ModelRetryPolicy`, `modelRetryDefaults` and `CurrentModelRetryPolicy`, with default-bound aliases `LLM_REQUEST_TIMEOUT_MS` and `LLM_CALL_BUDGET_MS`.
- Transport: the `ModelsTransport` port (`ModelsFetch`, `WebSocketProxy`), `ModelsTransportLive` with its options (`HttpProxyOptions`, `ProxyUrlOption`) and errors (`ProxyInvalid`, `ProxyUnsupported`); `makeOpenAiCodexWebSocketHttpClient`, the subscription's WebSocket client over a transport.
- Auth: the `AuthStore` port (`Credential`, `AuthError`), `LocalAuthStoreLive`, `MemoryAuthStoreLive` (`MemoryAuthOptions`) and the `HostCredentials` port (`CredentialInput`, `CredentialInputs`, `AccountId`, `InstallationId`); for a store of the host's own, the refresh its `resolveKey` owes: `refreshCredential`, `isUsableAt`, `REFRESH_SKEW_MS`, `RefreshableProvider`, `OAuthCredential`. The subscription sign-ins: `beginAnthropicOAuth` (`OAuthBegin`), `parseAuthorizationInput` (`AuthRedirect`), `exchangeAnthropicCode` and `refreshAnthropicToken` (`RefreshedTokens`), `beginOpenAiCodexOAuth` (`OpenAiCodexOAuthBegin`), `exchangeOpenAiCodexCode` and `refreshOpenAiCodexToken` (`OpenAiCodexTokens`), each request taking `TokenRequestOptions`.
- Settings: the `SettingsStore` port (`EngineSettings`, `SettingsError`, `ModelRole`, `SETTINGS_KEYS`, `SettingsKey`), `LocalSettingsStoreLive`, `MemorySettingsStoreLive`; for a store of the host's own, the checks the port's writes make: `applyRole`, `applySetting`, `coerceSettingValue`, `roleSelection`, `settingsFromRecord`, `ROLE_FIELDS` (`RoleField`, `SettingValue`).
- The OpenAI-compatible client, the `@xandreed/plugin-models/compat` subpath (`src/compat/index.ts`) and not the root: `makeCompatLanguageModel` (`CompatConfig`), `toChatMessages` (`ChatMessageOptions`), `promptWithImageLabels`.
- Kits, the `@xandreed/plugin-models/conformance` subpath (`src/conformance/index.ts`) and not the root: `authStoreConformance` (`AuthStoreConformanceOptions`, `AuthStoreRefreshProbe`), `settingsStoreConformance` (`SettingsStoreConformanceOptions`) and `modelRequestConformance` (`ModelRequestSubject`), each tagged `@public` (`quality/exports-have-consumers` runs on the entry). They are built with core's `check` and `ConformanceFailure` (`@xandreed/core/conformance`); store fixtures use `randomUuid` (`@xandreed/core/internal`).

The three entries name each export, and `quality/exports-have-consumers` checks each one: the docs, the scripts (the plugin reference, the packed consumers, `verify:packages`) and the sdk's tests import some, and the rest, which no first-party code imports, are tagged `@public` at their declarations (`modelsPlugin`'s tag covers the default export). How the plugin routes and sends a call stays inside the package: the provider builders (`buildProvider`), request engine and ephemeral attempt state (`resilientRequest`, `ModelRequestCall`), the subscription's wire (`makeOpenAiCodexLanguageModel`), the proxy's resolution (`resolveProxy`, `proxyFor`) and the OAuth protocol's constants.

## Erasure files

- `src/llm/router.ts`, `src/llm/providers.ts`: one routed `LanguageModel` over arbitrary provider services, with reshaped options and generic `generateText`/`generateObject`/`streamText` signatures; `withImageLabels` re-wraps those methods and a cache-control message is rebuilt with `Prompt.makeMessage`. Only this existing SDK boundary narrows the precise HTTP client/reader `HttpClientError | AiError | TurnError` channels; recorder failures use the original-error defect bridge at fixed SDK signatures.
- `src/llm/compat.ts`, `src/llm/openAiCodex.ts`: effect/ai's generic `LanguageModel` surface over hand-built clients, and `Tool.Any`'s description/schema. Codex applies the request policy after its final WebSocket/base-URL/auth transform and narrows SDK reader/client types only at this existing boundary.
- `src/transport/undici-fetch.adapter.ts`: npm undici's fetch typed as the global one; its classes differ, so nothing downstream may rely on `instanceof Response` or `Headers`.

## Tests

- Kits: `authStoreConformance` on both auth stores (`src/auth/memory-auth.adapter.test.ts`), `settingsStoreConformance` on both settings stores (`src/settings/memory-settings.adapter.test.ts`), core's `modelCatalogConformance` (`src/llm/modelCatalog.test.ts`), and those store/catalog kits on the plugin's own stores (`src/plugin.adapter.test.ts`). `modelRequestConformance` tests one mixed-error counter, permanent structured status errors and execution-time policy overrides. Each shipped kit has careless-subject self-tests beside it.
- Accounting: `model-usage.entity.functions.test.ts`, `model-completion.adapter.test.ts` and `transport/model-call-accounting.adapter.test.ts` prove coverage, cumulative usage, record-before-retry, discarded completions, child identities, sticky ACK results and stream cancellation/finalizer failures. Shared failure/retry source and packed fixtures check one durable row per physical send and preserve selected usage.
- Overflow: `provider-overflow.adapter.test.ts` checks actual route identity and known limits across text, object and stream failures, raw HTTP 200 interception, configured aliases, effective output overrides and unknown compat bounds. The shared SDK and packed `context-overflow` journey proves smaller requests, fresh headers, the actual fallback's limits, one resend, visible-output refusal and separate billing.
- Policy and transport: schema/transition tables, request-engine unit tests and compat/Codex boundary tests cover delays, scoped cancellation, body reads, direct SDK tools and typed failures. `packages/sdk/src/model-retry.journey.test.ts` drives the shared sixteen-case local HTTP Agent fixture; it checks forwarded abort signals on Bun1.3.0 and Node, with socket-close proof on Node. Native Bun1.3.0 may retain an aborted header-wait socket; fixture cleanup closes it explicitly.
- `packages/sdk/src/models-plugin.test.ts` drives the plugin under `Agent.define`; the sdk golden uses a scripted model, so none of the text above is in it. `verify:packages` runs `scripts/models-consumer.fixture.mjs` and `scripts/proxy-consumer.fixture.mjs` on Node over the packed package, plus shared Messages, failure and retry fixtures on Node and Bun. The proxy fixture inspects actual scoped undici zero-timeout options and global-dispatcher isolation; CI reruns `src/llm/openAiCodexWebSocket.test.ts`, `src/plugin.adapter.test.ts` and `src/transport/models-transport.adapter.test.ts` on Bun 1.3.6. Key-free fixtures establish protocol and control-flow contracts, not live-provider acceptance.
