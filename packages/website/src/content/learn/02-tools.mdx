<Step n={1} id="build" title="What you will build" focus="code">

In lesson 1, a turn called the model once. With **tools**, the model can ask for something first, such as a sum worked out or a note saved, and answer from the result. So the turn becomes a **loop**:

1. ask the model;
2. if it asked for tools, run them, store their results, and go back to 1;
3. if it only answered, the turn is done.

Nothing new is hidden behind this. The tools are Effect AI's own `Tool` and `Toolkit`, declared in **tools.ts**. The loop is yours, in **agent.ts**. The kernel only stores what happened: the model's calls and the tools' results, as records of the conversation.

</Step>

<Step n={2} id="model" title="Pick a model" focus="model">

**Echo** follows rules, so you can rely on it:

- a sum goes to the calculator;
- "remember …" goes to remember;
- a question about your notes goes to recall;
- after a tool answers, it repeats what the tool said.

The models on your machine are given the tools in their system text, one line each with an example call, and asked to answer with a `<tool_call>` block. A model this small often skips the tool and answers on its own: a 0.5B model may still get 12 * 3 right. Sometimes it writes a call wrong. A wrong call is stored as a failure, and the model can try again. Hosted models are trained for tools and use them reliably.

</Step>

<Step n={3} id="tools" title="The tools" focus="code" file="tools">

**tools.ts** declares each tool with `Tool.make`: its name, a description the model reads, what it takes (`parameters`) and what it returns (`success`, and `failure` for one that can fail).

`Toolkit.make` groups them. `tools.toLayer({ … })` says what each does when called, and runs here in your browser.

Like the system text, the tools are **code**. They are offered to the model in every call, and never stored.

The notes live in the file, in `notes`, not in the journal. Rebuild runs the file again, and they are gone. That is a tool's own state: the journal holds the conversation, and what the tools keep is theirs.

</Step>

<Step n={4} id="loop" title="The turn is a loop" focus="code">

Read `turn` in **agent.ts**. Each time round the loop:

1. **memory builds the context**, exactly as in lesson 1;
2. **the model is called** with `toolkit` and `disableToolCallResolution: true`: the model sees the tools, but effect/ai runs none, because your loop does. `toolCallValidation: "deferred"` lets a call the model got wrong through, so it can be answered;
3. **the answer is stored** with the calls it made (`assistantMessage(text, { toolCalls })`). No call means the turn is done;
4. **each call runs** through `runTool`, and **its result is stored** (`toolResult`). A tool that fails, an unknown tool, or wrong parameters all come back as a result marked as a failure. The model reads it like any other answer, and the turn goes on.

`MAX_STEPS` stops a model that keeps asking.

</Step>

<Step n={5} id="watch" title="Watch it run" focus="context" wide={true}>

Ask **"What is 12 * 3?"** and open the **Context** tab. The turn now has more steps: the model's first call, the tool's result, then a second call. Pick a model call above the columns to see each one's context and prompt.

In the **Prompt** column of the second call, the model's tool call and the tool's result follow your message. Both come from the journal: hover one and its record lights up. The calculator's answer sits in the conversation like anything else that was said.

Then ask **"What is 1 / 0?"**: the failure is the tool's answer, and the turn goes on.

</Step>

<Step n={6} id="steer" title="Steer a long run" focus="chat">

A coding agent may run fifty steps over ten minutes. You need to tell it something without waiting for it to finish.

At the end of each step, the turn takes every message you sent meanwhile (`chat.drain`) and stores them in the same turn. The model sees them at its next call.

<p class="learn-try"><button class="btn btn-primary" type="button" data-exp="slow-calculator">Make the calculator slow</button></p>

Ask **"What is 6 * 7?"**. While the calculator works, send **"Also, what is 10 / 4?"**. One turn answers both. The Context tab shows a **Steered** step where your message joined.

**Send three at once** does the same: the messages arrive while the first turn runs its tool, so they join it.

</Step>

<Step n={7} id="memory" title="Calls and results in memory" focus="code" file="memory">

**memory.ts** is lesson 1's flat memory, with one rule added: `paired`.

A provider refuses a tool call that no result answers, and a result whose call is missing. Both happen: Stop or Rebuild can end a turn while a tool runs, and a memory that keeps the last *n* messages can cut between a call and its result. `paired` sends a call only with its result.

The journal still keeps everything. The memory kit checks this rule (`pairs`) on every memory.

</Step>
