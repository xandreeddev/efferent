# @xandreed/plugin-memory-window

Windowed conversation memory: a `ConversationMemory` over core's memory log that stores every message and tool result whole, and shows the model the current turn verbatim (a result longer than `boundOnWriteChars` as its first characters and a locator, from the first request that includes it), earlier turns through their tools' compact views (from each turn's start with `compactPreviousTurn`; without it, only once a request passes its budget) and, only under budget pressure, spill previews and a ledger in place of the oldest turns. It also contributes core's `recall_context`, which reads a shortened result back. Node 24 and Bun; layer `plugin-memory-window` in `foundry.config.ts` (imports core only).

## Rules

- The policy only decides: `windowPolicy` returns `CompactionAction`s as data, and core's `openLogSession` records and renders them.
- `open` is a `memory.open` span (`Effect.fn`), as in every memory plugin.
- Bounding a result as it is written is core's (`recordTail`, `packages/core/AGENTS.md`): the policy only sets `MemoryPolicy.boundOnWriteChars` from the option (16,000 by default; `0`, or a config written without the key and given to `windowPolicy` as it is, sets none), and core records each bound as this strategy's own `Spill`. Change what is bounded, or the notice, in core.
- `decide` reads what each result shows from core's `shownViewsOf` (a compact view, a spill's or a bound's preview, a digest), never from the view's length alone. Order spill candidates by the text they show, largest first. A result shown through other text is spilled only when the `previewChars` preview is strictly shorter than that text, so a bounded result is spilled again under pressure, a result already spilled is not, and a second `maintain` over the same log decides nothing. At turn start a result takes its tool's compact view once; one shown through a preview (a bound's or a spill's) is asked again each turn start and takes it only when it is strictly shorter than that preview; one already shown through a compact view is never asked again (no `compact` call, so the turn-start pass stays proportional to the results not yet compacted).
- `compactPreviousTurn: false` means never at a turn's start, not never: a turn start then decides no compact view, so a request that fits its budget is byte for byte the one before it with more messages after, and a provider's cached prefix holds. Under budget `decide` returns before it asks any tool for a compact view. Over budget, with the option on or off and at every phase, earlier turns' results take their compact views before anything is spilled or dropped. Only results of turns before the current one, never a pinned one, one that already shows its compact view, or one of a turn this strategy already dropped (`DropTurns`: it is not shown, so nothing would be freed). A compact view is taken only when it is strictly shorter than the text the result shows (`shownViewsOf`: its view, a bound's or a spill's preview, a digest), and a tool with no compact view is left alone. The fewest that fit are taken, the one that frees the most characters first (equal savings in log order), as one `CompactViews`, found by halving so the renders stay logarithmic in the number of earlier results; when all of them together do not fit, all are taken and the later stages start from there. A turn start with `compactPreviousTurn` has asked every earlier result already, so the pressure pass asks none of them a second time. The turn-start rule is unchanged and looser: a result still shown whole or through a digest takes its compact view whatever its length.
- Keep the pressure order: compact earlier turns (at turn start with `compactPreviousTurn`, else when a request passes its budget), spill the current turn's largest results, drop the oldest turns. With `currentTurnFirst`, compact earlier turns, then drop the oldest turns, and spill the current turn's largest results only when dropping every earlier turn still does not fit: the fewest spills first, then the fewest dropped turns. Use `scaledTokens` with the same accepted observation at every candidate comparison; reserves are already outside the message budget.
- Normal `step`/`turn-start` maintenance fails with `context.budget` if the current turn still cannot fit. `turn-end` and `overflow` are advisory: return safe reductions even when irreducible current pressure remains. The next actual dispatch remains strict.
- Never spill a `recall_context` result or a pinned one: the recalled page is what makes a spill lossless.
- `WINDOW_STRATEGY.version` is `3` (it bounds results as they are written, spills and compacts by what a result shows, and compacts earlier turns under pressure whatever `compactPreviousTurn` says); bump it when a decision changes. Recorded version 1 and 2 actions and saved recipes keep replaying without rerunning the policy.
- `currentTurnFirst` keeps the strategy id `window` (so compactions recorded under either order keep applying) and suffixes the version: `3+current-turn-first`. The version is in every request header (`strategyVersion`) and `context.built`, so a request's fingerprint, a trace and a replay tell the two orders apart. A config is read through `windowPolicy(config).strategy`, never `WINDOW_STRATEGY` alone.
- The recall tool, its paging, its guard against text the turn still shows and the spill preview are core's (`packages/core/src/memory/recall.entity.functions.ts`): `recallCapability` is `recallCapabilityOf` under this plugin's capability id, `@xandreed/plugin-memory-window/recall`, which never changes; the policy writes a spill's preview with `spillPreview` and tells a recalled page by `RECALL_TOOL`. Change their text in core, with its pins. The guard reads a spill's shown length back from its preview, and only from one `spillPreview` wrote: a spill written any other way is served from its start again. A refusal is the call's recorded result and outlives what this policy shows of the result (a second spill under pressure, a compact view at a later turn's start or under pressure), so core's `ResultShown` texts hold no offset and send the model to the one the result's shortened form shows when the reply is read.
- A decision that changes what the sdk goldens show is re-recorded with `EFFERENT_UPDATE_MODEL_GOLDEN=1` and the diff reviewed.

- `packages/sdk/src/recall-guard.journey.test.ts`: through `Agent.define` under this strategy and the summary one, a model that asks for shown text is told where to read on and reads the next page, one that keeps asking (inside the result's shown start, or stepping inside a page it read) is stopped by the step loop's breaker before the step limit, and a result of an earlier turn is served as before. - `packages/core/src/memory/memory-session.test.ts`: what `recordTail` bounds and what it leaves whole; `packages/sdk/src/bound-on-write.journey.test.ts`: four results far above the bound in one turn through `Agent.define`, within budget, each request's prefix unchanged, the next page read with `recall_context`, `boundOnWriteChars: 0`, calls made together in one step and the next turn's first request, and a tool's own annotation.
