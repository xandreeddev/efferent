The kernel, a small core with every other part a plain Effect layer, ships as two new entries beside the existing engine, which neither imports nor is imported by it: `@xandreed/core/kernel` (ids, `Message`, the event envelope, the `JournalStorage`, `Sessions`, `Memory` and `Loop` contracts with a conformance kit each, the pure rules, `Core`, which is events only: `publish`, `on` and `events`, and `kernel({ system, capacity? })`, the layer that provides `Core` and `Settings`) and `@xandreed/sdk/kernel` (the stock plugins `inProcessJournal`, `sessions`, `windowMemory`, `stepLoop` and `inbox`, each a layer whose type says what it needs, and `scriptedModel`, a model that follows a script and calls no provider). A host composes the layers with `Layer.provideMerge`, and a stack whose type is written out does not compile when a part is missing. `Memory` is one function, `build(session, step)`, that keeps nothing. The inbox queues messages per session and answers them in order, each in a turn of its own. Events are named by the plugin that writes them and the set is open: a plugin defines its own with `storedEvent` and `liveEvent`. A request is stored as pointers into the journal, so each message's text is stored once. It is a first cut, with journals kept in the process and no tool execution, and it will change as the parts it leaves out return; `docs/kernel.md` is its direction document. Neither entry imports a `node:` or `bun:` module.
