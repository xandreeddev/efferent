The kernel, a small core with every other part a plain Effect layer, ships as two new entries beside the existing engine, which neither imports nor is imported by it. `@xandreed/core/kernel` holds what every agent has, whatever its workflow: ids, `Message`, the event envelope, the `JournalStorage` and `Sessions` contracts with a conformance kit each, reading a journal, `inspectionOf`, and `Core`, which is events only (`publish`, `on` and `events`), with `kernel({ capacity? })`, the layer that provides it. `@xandreed/sdk/kernel` holds the workflow contracts, each in a contract folder with its kit (the loop's `Loop`, `Settings` and `settings({ system })`, the conversation's events and the request vocabulary; memory's `Memory`; the inbox's `Inbox`), and the stock plugins `inProcessJournal`, `sessions`, `windowMemory`, `stepLoop` and `inbox`, each a layer whose type says what it needs, with `scriptedModel`, a model that follows a script and calls no provider. A plugin imports contracts and core, never another plugin. A host composes the layers with `Layer.provideMerge`, and a stack whose type is written out does not compile when a part is missing. `Memory` is one function, `build(session, step)`, that keeps nothing. The inbox queues messages per session and answers them in order, each in a turn of its own. An event is named by the owner of the contract that defines it (`core.session.turn.started`, `plugin.loop.request.sent`) and the set is open: a plugin defines its own with `storedEvent` and `liveEvent`. A request is stored as pointers into the journal, so each message's text is stored once. It is a first cut, with journals kept in the process and no tool execution, and it will change as the parts it leaves out return; `docs/kernel.md` is its direction document and `docs/adr/0002-core-owns-state-plugins-own-workflows.md` records where core ends. Neither entry imports a `node:` or `bun:` module.
