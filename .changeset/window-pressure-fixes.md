Over budget, the window takes a compact view only when the request's estimate falls with it: it must be shorter than the text shown and take at least one estimated token less of the request's JSON, so a shorter compact view full of quotes or newlines no longer raises the estimate and costs extra spills and dropped turns. A decision that drops turns records no compact view of a result in a turn it drops, and a turn's start asks for none in a turn already dropped; the requests are unchanged. Both change what the window decides, so `WINDOW_STRATEGY.version` is `4` (`4+current-turn-first` with `currentTurnFirst`): a host that pins a request header, `context.built` or its journal re-records the pin. The documentation says what is recorded when all compact views together do not fit, that requests within budget are not rewritten while bounds are still recorded, and that the request prefix holds across a turn's start only while everything the previous request showed is still shown, which a turn context of the previous turn is not under the default `turnContext: "current"`.
